Self-hosted memory for AI agents

Memory your AI can check.

Most AI memory keeps a few notes the model wrote about you. Throughline keeps the original records — your chats, email, calendar, notes and voice notes — in one database on your own machine. Any agent can then search them, count them and quote them back with a date and a source.

Agent memory, explained

Three common ways AI “remembers” you, and where they fall short.

If you use an assistant like Grok, Muse or a Hermes agent, its memory almost certainly works like one of these. Each is useful. Each has the same blind spot.

Built into the assistant

Saved memories

The assistant writes short notes about you (“prefers window seats”, “has a dog called Biscuit”) and adds them to future chats.

Good at
No setup. Remembers preferences and the big facts.
Falls short
It only has what it chose to write down. Exact dates and wording are usually gone, and the memory stays inside one app.
Agent frameworks

Memory files

The agent keeps a Markdown file, often called MEMORY.md, edits it as it goes, and reads it at the start of every session.

Good at
Easy to read and fix by hand. You own the file.
Falls short
It has to stay small enough for the prompt. Rules like “don't duplicate” or “keep this private” are only instructions the model has to remember.
Knowledge bases like GBrain

Agent-written wikis

A model writes and maintains linked pages about people, projects and events, and the agent searches those pages.

Good at
A rich, readable picture of your world, good for big-picture questions.
Falls short
Pages are only as good as the model's upkeep. Without checks they drift, and counts and dates depend on what was written.

The blind spot is the same in all three: the memory is the model's notes about your life. Throughline keeps the record itself, and builds the notes on top, each one linking back to its source.

How it works

The record at the bottom. Everything else is built on it.

Connectors bring your data into one PostgreSQL database. Throughline builds the useful layers on top, and agents reach all of it through a small set of tools.

  1. 01

    Nothing is overwritten

    Every message, email and event is stored as it arrived. An edit becomes a new version and the old one is kept. Corrections are saved as notes next to the record, not over it.

  2. 02

    Summaries cite their sources

    People, pages and tables are built from the records and point back to them. Every result is marked as an original record, a summary or a model's guess.

  3. 03

    Rules live in the database

    Duplicate protection, audit logs and privacy are enforced by PostgreSQL itself. A prompt can't talk its way past them.

What's inside

The layers on top of the record.

Each layer is generated from your records, points back to them, and can be corrected by you.

People

One person, every account.

The same friend on Signal, email and in your voice notes becomes one person. Agents get a brief for anyone: how you know them, when you last talked, and what's still open.

  • Matches you're not sure of stay unconfirmed until you approve them.
  • Merges and splits can always be undone.
Lenses and Pages

Notes that keep themselves up to date.

A Lens is a question you ask once, like “every book a friend recommended”. Throughline keeps a table of answers up to date as messages arrive, each row linked to the messages behind it. Pages are wiki pages for people, days, events and projects: a summary on top and a dated timeline below.

  • Every citation must point to a record the AI was shown, and quotes must really appear in it.
  • Fix a row and your fix is locked. The Lens learns from it.
  • Choose how often they update, with per-run and monthly spending caps.
  • Inspired by GBrain's compiled wiki pattern, and every page can also be saved as Markdown files.
Classifiers

Tag the noise. Keep the record.

Classifiers label messages automatically, for example the TV talking in the background of a voice recording, a newsletter, or an email that needs a reply. Labels sit next to the record and never change it.

  • Write one as a yes-or-no question for an AI, or let your agent write a small Python check that goes live once you approve it.
  • When you overrule one, your decision sticks.
Coverage

It knows what it's missing.

Throughline tracks which sources synced and when. If a connector goes quiet, it tells you, and agents say “not found in the sources I have” instead of “that never happened”.

  • Alerts when a source fails, goes silent or falls behind.
  • Encrypted backups with automatic restore tests.
Privacy

Each agent sees only what you allow.

Give a work agent your work email and calendar, and nothing else. The database enforces it, so even a raw SQL query from that agent can't reach anything else.

  • A separate key for each agent. Limit it to the sources and threads you choose, and revoke it on its own.
  • Sensitive labels are hidden by default. Medical, financial and intimate content stays out unless you grant it, and grants can expire.
  • Out of the box, nothing leaves your machine. AI providers are optional, only hosts you allow can be reached, and labelled content can be kept away from cloud models.

Get started

Up and running in one command.

The installer sets up PostgreSQL, the API and the background jobs with Docker, generates passwords, and prints your owner key once.

  1. Install

    Run the installer. Running it again later never replaces passwords or keys, and updates snapshot the database first and roll back on failure.

  2. Add sources

    Finish setup in your browser: pick connectors, pair the desktop companion, and choose which Lenses and Pages to keep.

  3. Connect your agents

    Create a key for each agent and add Throughline over MCP, or hand any agent the included skill file and the HTTP API.

Terminal
# 1. From the repo, install Postgres, the API and jobs
$ scripts/install.sh

# 2. Finish setup in your browser:
#    http://127.0.0.1:8000/ui/welcome

# 3. Connect an agent with the key you made for it
$ claude mcp add throughline --transport http \
    http://127.0.0.1:8000/v1/mcp \
    --header "Authorization: Bearer $AGENT_TOKEN"
Questions

Good to know.

Do I need an OpenAI or Anthropic key?

No. Storage, keyword search, timelines, people, coverage and SQL all work with no AI provider and no outbound network calls. Meaning-based search, Lenses, Pages and AI classifiers are optional. They can use a hosted provider or a local model through any OpenAI-compatible server such as Ollama or LM Studio, and you can cap the monthly spend.

Does it replace my assistant's memory?

It sits underneath it. Your assistant can keep its own notes. Throughline gives it a place to check them against what actually happened, and to look up anything it never wrote down.

Which agents can use it?

Anything that speaks MCP — such as Claude Code, Claude Desktop, Cursor, Codex and Hermes — can connect directly. Any other agent that can make HTTP requests can use the API with the included skill file, which teaches it which tool to use for which question. Hosted chat apps that don't support external tools can't connect directly.

Who is it for?

One person's life per install, run on hardware you control. It's built for people comfortable running a Docker app, and it isn't meant to be exposed directly to the internet. Use a VPN or an HTTPS reverse proxy for remote access.

Is it available now?

Yes. Throughline is open source (GPL-3.0-or-later) and available on GitHub.
